## 目标
实现 02 §10：从入口遍历，产出画面边（含悬空边）与断链记录，作为 P8 接入构建管线。

## 实现要点
1. Core 只认识领域边的 **kind 与 json 结构**（02 §9 各节定义），不认识 POS 名称；终端 peer 关系来自配置 `terminals`。
2. 遍历键 `(methodId, terminal, branchFilterHash)` 去重；同一入口内不重复进入。
3. 处理优先级严格按 02 §10.2；`domainHandled` 目标不进入。
4. 接收方条件文本：`{终端中文名}当前画面 ∈ {画面ID, …}`（employee = 员工面，customer = 客面）；Stage 条件：`当前 Stage = {stage}`。
5. 链确认度传播：遇到 candidate 派发、断链、部分匹配的分支 → 之后所有步骤与最终边为 candidate。
6. 画面边按 02 §10.4 的 `(from, to, trigger.kind, controlId)` 分组保留前 `maxChainsPerScreenEdge` 条。
7. 断链 ID 按 02 §10.5；同一断链被多条边引用只写一次。
8. 所有 ChainStep 都要有 `evidenceId`。
9. 不变量检查（构建末尾）：有断链的边必须是 candidate；违反 → 内部错误（这是实现缺陷，不得放宽）。
