## 目标
实现 05 §6 的自动验收脚本、报告核对脚本与期望文件；在生成机器上用 MiniPos 期望文件跑通。

## 前置
T20

## 产出
- `acceptance/run_acceptance.py`
- `acceptance/check_report.py`
- `acceptance/strip_comments.py`（C# 去注释：删除 `//` 行注释与 `/* */` 块注释，正确跳过字符串与字符字面量、逐字字符串 `@"…"`、插值字符串）
- `acceptance/expectations.pos.json`（A-01 … A-19 的期望，值取自 03 §13 与 05 §6.2）
- `acceptance/expectations.minipos.json`（同结构，值取自 05 §4）
- `acceptance/README.md`

## 实现要点
1. `run_acceptance.py --project P --cli C --expect E [--profiles android-onsite,windows-editor] [--skip A-02,…]`：逐项执行，记录每项的命令、退出码、耗时、原始输出（`results/<时间戳>/A-xx.json`），比较期望，生成 `summary.md`（表格：ID、结果 PASS/FAIL/WARN、说明）与 `summary.json`。
2. 期望文件描述的是**断言**（例如“data.paths[0].hops[0].edges 中存在 chain 含 type=Payment_SSAW0089_Presenter 且 detail 含 SSAW0903.To.SSAW0907”），用一个小型断言 DSL（JSON）：`exists`、`equals`、`contains`、`count>=`、`allNot`；JSON 路径用点号 + `[*]`。
3. 交叉核对项（A-11 … A-16）在脚本中实现：去注释后的正则计数；`#if TeamUI … #endif` 区间定位（支持嵌套 `#if`）；差值逐条列出到 summary。
4. 峰值内存：若环境中**已安装** `psutil` 则使用；未安装 → 该项记 WARN。**不得自行安装 psutil**（不在 02 §1.2 允许列表中）。
5. `check_report.py <报告.md> <A-06输出.json>`：从报告中提取所有反引号内的标识符与 `文件:行`，检查其是否出现在 A-06 输出中；输出未找到的列表，有则退出码 1。
6. MiniPos 期望下 A-11 … A-16 的交叉核对也要能跑通（MiniPos 中的 `#if TeamUI` 只有 1 处）。
