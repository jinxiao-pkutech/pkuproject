# T00 解决方案骨架与环境检查

## 目标
建立可构建、可测试的空解决方案，固定项目结构与依赖规则。

## 前置
无

## 必读
- `CLAUDE.md` 全文
- `docs/02_架构设计书.md` §1

## 产出
- `ScreenFlow.sln`、`Directory.Build.props`、`.gitignore`（忽略 `bin/ obj/ publish/ .screenflow/ acceptance/results/`）
- `src/ScreenFlow.Core/ScreenFlow.Core.csproj`、`src/ScreenFlow.CSharp/…`、`src/ScreenFlow.UnityPos/…`、`src/ScreenFlow.Cli/…`（各含一个占位类）
- `tests/ScreenFlow.Core.Tests/`、`tests/ScreenFlow.CSharp.Tests/`、`tests/ScreenFlow.UnityPos.Tests/`、`tests/ScreenFlow.Cli.Tests/`、`tests/ScreenFlow.Architecture.Tests/`
- `tools/check-env.ps1` 与 `tools/check-env.sh`

## 实现要点
1. `Directory.Build.props`：`net8.0`、`Nullable=enable`、`TreatWarningsAsErrors=true`、`LangVersion=latest`、`Deterministic=true`、`ImplicitUsings=enable`。
2. 项目引用严格按 02 §1.1；NuGet 只引 02 §1.2 列出的包（CSharp 项目引 Roslyn；Core 引 Sqlite）。
3. 测试项目引用对应源项目；`ScreenFlow.Cli.Tests` 引用 Cli。`ScreenFlow.Cli.csproj` 设置 `<AssemblyName>screenflow</AssemblyName>`、`<OutputType>Exe</OutputType>`，并把 `config/*.json` 作为内容复制到输出目录的 `config/` 下。
4. 架构测试 `Architecture_CoreHasNoRoslyn`：加载 `ScreenFlow.Core` 与 `ScreenFlow.UnityPos` 程序集，断言 `GetReferencedAssemblies()` 中没有以 `Microsoft.CodeAnalysis` 开头的项；`ScreenFlow.UnityPos` 不引用 `ScreenFlow.CSharp`。
5. `check-env`：输出 `dotnet --list-sdks`（必须含 8.x）、`python --version`（3.11+）；不满足时退出码 1 并打印缺失项。

## 测试（新增）
- `Architecture_CoreHasNoRoslyn`、`Architecture_UnityPosHasNoCSharpExtractor`（Trait Task=T00）

## 冒烟命令
```bash
pwsh tools/check-env.ps1 || bash tools/check-env.sh
dotnet build ScreenFlow.sln -c Release
dotnet test ScreenFlow.sln -c Release --filter "Task=T00"
```
环境检查失败 → 直接 `BLOCKED`，备注写明缺失项（这不是代码问题，不要尝试修正）。
