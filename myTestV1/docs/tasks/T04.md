## 实现要点
1. 所有命名空间、类名、方法签名、调用写法按 03 文档；夹具中的类允许精简方法体，但**调用形态不得改写**（例如必须保留委托字段订阅、`?.` 调用、目标类型 `new()`、集合初始化器、对象初始化器、条件拼接、`nameof`）。
2. 外部库桩放 `Assets/Stubs/`，命名空间与真实一致；只写编译所需成员。`UnityEngine.UIElements.Label` 与 `Button` 需有 `LocalizationKey`、`Title`、`TitleButton` 属性以及 `Q<T>(string)`/`Query<T>(string)` 方法；`Button` 有 `event Action clicked`。
3. 每个源文件至少一处变更标记注释（`//▼ ADD 2024.01.17 Fixture@Test 夹具` / `//▲ ADD …`）。
4. rsp：
   - `ed01.dag/Assembly-CSharp.rsp`：`-target:library`、`-out:"Library/Bee/artifacts/ed01.dag/Assembly-CSharp.dll"`、`-define:UNITY_EDITOR`、`-define:UNITY_2022_3_68`、`-define:TeamUI`、`-define:DEBUG`、`@Library/Bee/artifacts/ed01.dag/common.rsp`、`-r:"Library/Missing/Nothing.dll"`、全部源文件（一半带双引号、一半不带）。
   - `common.rsp`：`-langversion:9.0`、`/unsafe`、`-nullable:disable`。
   - `Assembly-CSharp.mvfrm.rsp`：任意内容（被排除）。
   - `an01.dag/Assembly-CSharp.rsp`：同上但 define 为 `UNITY_ANDROID`、`UNITY_2022_3_68`、`TeamUI`，无 `UNITY_EDITOR`。
   - rsp 中列出 `Assets/Common/Legacy/KEY01_KeyCalculator.cs`（T05 才创建；本任务的编译测试临时排除该文件）。
5. 编译测试：用 `Microsoft.CodeAnalysis.CSharp` 直接把 `Assets/**/*.cs`（排除 KEY01）+ 宿主 TRUSTED_PLATFORM_ASSEMBLIES 编译，preprocessor symbols = `UNITY_EDITOR`，断言 error 数 = 0；再用 `UNITY_ANDROID` 编译一次同样 0 error。（这个测试不依赖 T06/T07 的代码。）
