## 目标
实现 02 §7 的数据库：建表、批量写入、只读查询基础、原子替换、规范化导出、陈旧检测。

## 前置
T02

## 必读
- `docs/02_架构设计书.md` §2（P4、P9）、§3、§7（全部）

## 产出
- `src/ScreenFlow.Core/Storage/`：`Schema.sql`（嵌入资源，02 §7.2 + §7.3 全部表）、`IndexDb`（打开/创建、PRAGMA）、`IrWriter`（IR 记录 → 表，10,000 条一批事务；`json` 列存完整记录）、`DomainWriter`（领域表写入 API）、`IndexReader`（按 ID/索引列查询的基础方法）、`AtomicBuild`（写 `.building` → 成功后替换）、`Dump`（§7.5）、`Fingerprint`（§7.6）
- `tests/ScreenFlow.Core.Tests/Storage/`

## 实现要点
1. 入库前按 ID 排序（`IrWriter` 先在内存中按类型分桶收集，再排序写入；大量记录时用分批排序 + 有序写入，保证同一输入同一结果）。
2. ID 冲突：同 ID 不同 `json` → 抛 `IdCollisionException`（错误码 `E_ID_COLLISION`）。同 ID 同内容 → 忽略。
3. `evidence` 由 `IrWriter` 从所有带 span 的记录派生（ID = `EvidenceId`）。
4. `assigns.target_symbol_id` 按 02 §7.2 的规则从 target Value 推导。
5. `Dump`：排除 `meta.builtAt`；行格式 `表名\t规范化JSON`；返回 SHA-256。
6. `Fingerprint`：输入为文件列表 + config 目录，输出 `(count, totalBytes, maxMtimeTicks, configHash)` 的字符串；比较函数。
7. 构建期 `synchronous=OFF`，完成后 `ANALYZE`，再切 `WAL/NORMAL`。
