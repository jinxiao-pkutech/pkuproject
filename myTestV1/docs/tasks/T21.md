## 产出
- `python/pyproject.toml`（包名 `screenflow-mcp`，依赖 `mcp>=1.2,<2`；dev 依赖 `pytest>=8`）
- `python/screenflow_mcp/__init__.py`、`__main__.py`（`--selftest` 与 stdio 服务入口）、`server.py`（FastMCP 注册 04 §2 的全部工具）、`cli_runner.py`（子进程调用）、`schemas.py`（参数校验）、`truncate.py`（60,000 字符截断）
- `python/tests/`：`fake_cli.py`、`test_runner.py`、`test_tools.py`、`test_truncate.py`、`test_selftest.py`

## 实现要点
1. 工具函数签名与 04 §2 完全一致；`description` 用中文，含“confidence 必须原样转述”。
2. `cli_runner.run(args: list[str]) -> dict`：`SCREENFLOW_CLI` 可以是 `.exe` 路径或以 `.dll` 结尾（此时前置 `dotnet`）；自动追加 `--db <SCREENFLOW_DB_DIR>/<profile>.db --profile <profile>`；`evidence get` 追加 `--project`。
3. 参数校验失败 → 不调用 CLI，返回 `E_INVALID_INPUT` 信封。
4. 截断：找出 `data` 中最长的列表，逐个移除末尾元素直到序列化长度 ≤ 60,000，设置 `meta.truncatedByMcp=true` 与 `meta.truncatedPath`。
5. 不得包含任何解析逻辑（不读数据库、不读源码）。
6. 测试全部使用 `fake_cli.py`（通过设置 `SCREENFLOW_CLI=python fake_cli.py` 的方式，runner 支持以 `.py` 结尾时前置 `sys.executable`）。
