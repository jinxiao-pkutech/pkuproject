# T01 配置文件与加载器

## 目标
生成 `config/profiles.json`、`config/unitypos.json`，并实现强类型加载与校验。

## 前置
T00

## 必读
- `docs/02_架构设计书.md` §4（全部）

## 产出
- `config/profiles.json`（内容逐字采用 02 §4.1，含 4 个 profile）
- `config/unitypos.json`（内容逐字采用 02 §4.2 的完整 JSON）
- `src/ScreenFlow.Core/Config/`：`ProfileConfig`、`ProfilesFile`、`DomainConfig`（UnityPos 用的配置以 `JsonElement` 原样持有，Core 只解析 `traversal`、`terminals`、`changeMarkers`）、`AnchorSpec`（类型/成员/集合锚点的统一模型）、`ConfigLoader`
- `tests/ScreenFlow.Core.Tests/Config/`
- `docs/PROGRESS.md`「待本机确认」：登记 02 §4.2 末尾列出的 4 项

## 实现要点
1. `ConfigLoader.LoadProfiles(path)`、`ConfigLoader.LoadDomain(path)`：`System.Text.Json`，允许注释与尾逗号；未知字段报错（防拼写错误）。
2. 校验：profile id 唯一；`selectPlatform ∈ {android, editor, any}`；`allowHostFrameworkReferences=true` 只允许 id 以 `fixture` 开头的 profile；`terminals` 的 peer 互相对应；`traversal` 各上限 > 0；`changeMarkers.pattern` 能编译为正则。
3. `AnchorSpec` 支持 02 §4.2 列出的 5 种形态；`member` 可为 `*`（所有成员）；`type` 可为 `*`（配合 fileGlob 表示文件中任意类型）。
4. `config-dir` 解析顺序：命令行 `--config-dir` → `<可执行文件目录>/config` → `<可执行文件目录>/../../../../config`（开发时）→ 当前目录 `./config`。
