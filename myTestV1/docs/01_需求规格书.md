# 01 需求规格书

## 1. 目标

对 SEJ 次世代 POS（Unity 2022.3.68f1、C# 9、Android、员工面/客面双终端）源码做**离线静态解析**。
给定开始画面 A、结束画面 Z，回答：

1. 从 A 到 Z 经过哪些画面（最多 K 条候选路径）；
2. 每一跳的完整处理链：源文件、行号、命名空间、类、方法；
3. 链上的 API 调用、硬件终端交互、外部数据入口；
4. 从主待机画面 `SSAW0001`（员工面）到 A 的前置路径；
5. 每一跳的 UI 事实：按钮日文显示文字、输入约束、错误码与错误文案；
6. **所有断链：断在哪里、为什么断、跨越了什么契约、从哪里重新回到可分析的代码。**

本项目会与硬件终端、微服务、Android 原生插件等交换数据，这些系统的源码不可得。工具不分析它们，只精确报告边界。

## 2. 使用者与使用方式

| 使用者 | 方式 |
|---|---|
| 测试人员 | 在 VS Code GitHub Copilot 中调用自定义 Agent，输入 A、Z，得到「路径与断链报告」 |
| Copilot 自定义 Agent | 通过 MCP（Python 实现）调用工具函数 |
| Python MCP 服务 | 以子进程调用 ScreenFlow CLI，透传 JSON |
| 开发者 | 直接使用 CLI 调试 |

## 4. 功能需求

### FR-01 编译输入加载
- 读取 `ProjectSettings/ProjectVersion.txt` 得到声明的 Unity 版本。
- 递归枚举 `Library/Bee/` 下的 `*.rsp`，识别其中属于 C# 编译的响应文件，解析出：程序集名、源文件、引用、编译符号、语言版本。
- 找不到可用编译输入时失败并返回 `E_NO_COMPILATION_INPUT`，提示用户用 Unity 2022.3.68f1 打开并编译项目。**不得自行伪造编译环境。**
- 预检诊断必须输出：版本不一致、缺失的引用、缺失的源文件、磁盘上存在但未被任何 rsp 包含的 `.cs`、非 UTF-8 文件。

### FR-02 分析配置
- 配置文件定义编译符号的增删和程序集过滤。
- `TeamUI`、`TeamUIDummy` 在两个配置中都必须移除。
- 当缓存的平台与配置声明的平台不一致时，快照标记为 `derived`，所有查询结果的 `meta` 中都要带出该标记。

### FR-03 语义抽取
- 按程序集构建 Roslyn Compilation，抽取符号、调用、对象创建、字段/属性读写、事件订阅、lambda、常量参数、方法内控制流。
- 注释与未启用的 `#if` 区域不产生任何事实。
- 被注释的变更标记 `▼ADD/▼MOD/▼CHG/▼UPD/▼DEL`（含日期、作者、Issue 号）作为元数据保存，不作为事实。
- 文件编码按 UTF-8(BOM) → UTF-8 → CP932 顺序判定。

### FR-04 项目专用关系识别
必须识别 `docs/03_源码事实手册.md` 中列出的全部机制：画面 ID、画面注册表、本地画面跳转、跨终端画面显示（通用事件 + 反射）、TCP 事件收发、键序表、DI、硬件设备、微服务 API、模型队列、按钮绑定、画面初始化 JSON、本地化表、错误文案、输入约束、SQLite、Android 原生调用。

### FR-05 画面操作图
- 节点 = `(终端, 画面ID)`。
- 边 = 一次用户操作或外部事件导致某终端显示的画面发生变化。
- 每条边带：触发方式、触发控件、处理链、条件、确认度、经过的断链。
- 跨终端的“对端当前画面”依赖要作为条件输出（例如：员工面当前画面须为 `SSAW0089` 或 `SSAW0281`）。

### FR-06 路径查询
- `path find`：A→Z 的 K 条候选路径（K 默认 5，可配置），找不到完整路径时返回**部分路径**并标明断在何处。
- `path prefix`：从待机画面（默认员工面 `SSAW0001`）到 A 的最优路径。
- 终端未指定且画面 ID 在两侧都存在时，分别计算并合并。

### FR-07 断链报告
每个断链必须给出：类别、原因码、断点（文件/行/命名空间/类/方法）、契约（接口、事件路径、apiKey、Topic、表名等）、请求/响应 DTO 类型（可得时）、固定模板生成的原因说明、回流候选及其确认度。

### FR-08 UI 事实
- 画面的控件、控件对应的处理方法、按钮显示文字（默认 `ja`，可指定其他语言）。
- 输入约束（最大位数、最大值、最小值、是否允许空）及其错误码、错误文案。
- 文字和约束无法确定时，明确返回“未解析”及原因，不得编造。

### FR-09 查询接口
CLI 与 MCP 提供：画面信息、画面控件、输入约束、画面出入边、路径查询、前置路径、断链列表、符号查找、调用方/被调用方、证据片段、文本查询、错误文案查询。

### FR-10 运行时 Agent
Copilot 自定义 Agent 接受 A、Z，按固定步骤调用 MCP 工具，输出「路径与断链报告」（格式见 `04_运行时Agent设计书.md`）。Agent 不读源码文件、不推测。

## 5. 非功能需求

| 编号 | 要求 |
|---|---|
| NFR-01 确定性 | 同一输入两次构建，节点/边/画面边/断链内容完全一致 |
| NFR-02 规模 | 约 9,400 文件、240 万行；按程序集流式处理，批量事务写库，进度输出到 stderr |
| NFR-03 内存 | 在 16 GB 机器上可完成全量构建：一次只保留一个程序集的 SemanticModel |
| NFR-04 查询速度 | 单次 `path find`（K=5）在已建索引上 10 秒内返回 |
| NFR-05 可追溯 | 每个事实至少带一条证据（文件 + 行列 + 片段哈希） |
| NFR-06 安全 | 输出中不含机器绝对路径、认证信息；XML 解析禁用 DTD/外部实体 |
| NFR-07 跨语言复用 | Core 不依赖任何语言解析库；语言抽取器通过 IR JSON 接入 |

## 6. 反编造规则（实现必须强制，测试必须覆盖）

1. 每个返回的事实都有确认度：`certain` / `candidate` / `unresolved`，且至少一条证据。
2. `certain` 仅限编译器语义唯一确定（静态/非虚调用、已解析的常量、唯一注册）。
3. 候选集完整返回，不得用启发式缩减为“最可能的一个”。
4. 结果被截断时必须返回 `truncated: true` 与触发的上限名称。
5. 注释与被注释的代码不是事实来源。
6. 索引中不存在的画面、控件、文字、约束、错误码，报告为“不存在”，不得合成。
7. 符号一律按 ID 解析，禁止按短名称匹配。
8. 快照与当前工作树不一致时，查询仍可返回，但 `meta.stale = true`。
