## 2. 构建管线（`index build`）

```text
P1 预检      rsp 发现/解析、版本比对、缺失文件、编码          (CSharp, §6.1–6.3)
P2 编译      按程序集构建 CSharpCompilation                     (CSharp, §6.4)
P3 抽取      语法树逐个 → IR 记录流                             (CSharp, §6.5–6.8)
P4 入库      IR 记录 → SQLite（批量事务 10,000 条/批）         (Core, §7)
P5 解析服务  派发候选、字段指向、实现关系索引                   (Core, §8)
P6 资源      UXML、画面初始化 JSON、本地化 YAML、错误文案 JSON (UnityPos, §9.9)
P7 领域适配  按固定顺序运行适配器 → 领域表                      (UnityPos, §9)
P8 画面图    入口 → 遍历 → 画面边 + 断链                        (Core, §10)
P9 收尾      统计、诊断汇总、meta 写入、原子替换数据库           (Core, §7.4)
```

- 适配器固定顺序：screens → enumerations → ui-bindings → di → keyseq → navigation → tcp → device → api → native → sql → queue → reflection → entries。
- 每个阶段向 stderr 输出 NDJSON 进度：`{"phase":"P3","done":1200,"total":9088,"elapsedMs":53012}`。
- stdout 只输出最终一个 JSON 文档（§11）。
- 数据库先写到 `<db>.building`，全部成功后原子替换 `<db>`；失败时保留旧库。
- 任何阶段可以产生诊断（§7.3 `diagnostics` 表），构建报告中汇总。

## 3. 确定性规则

1. 所有 ID 由内容哈希计算（§5.6），与运行顺序无关。
2. 并行处理语法树时，每棵树的结果单独收集，入库前按 ID 排序。
3. 遍历时邻接表按 `(priority, id)` 排序；Dijkstra/Yen 的平局按边 ID 升序。
4. JSON 输出：对象属性按类定义顺序；数组按规定的排序键（各节说明）排序。
5. 不写入时间戳到被比较的表中（时间只写在 `meta`）。
6. 测试 `Determinism_TwoBuilds_ProduceIdenticalDump` 比较两次构建的规范化导出（§7.5）。

## 5. IR（中间表示，语言无关）

### 5.1 传输格式

- NDJSON，每行一条：`{"k":"<种类>","v":{...}}`。
- 种类：`meta` `file` `symbol` `impl` `callsite` `assign` `creation` `cfg` `marker` `diag`。
- C# 抽取器在进程内直接把记录流交给 Core（`IAsyncEnumerable<IrRecord>`）；`ExternalProcessExtractor` 读取外部进程 stdout 的 NDJSON（未来的 Java/Python 抽取器）。
- `schema/ir-1.schema.json` 定义全部记录；Core 在入库前校验（外部抽取器必须校验，进程内抽取器在测试中校验）。

### 5.2 `symbol`

| 字段 | 类型 | 说明 |
|---|---|---|
| id | string | §5.6 |
| kind | enum | `namespace` `type` `method` `field` `property` `event` `local` |
| name | string | 简单名 |
| fqName | string | 完全限定名（方法含参数类型签名） |
| containerId | string? | 所属类型/方法（lambda 的容器是外层方法） |
| namespace | string? | |
| assembly | string | |
| isSource | bool | 源码中声明 = true；仅被引用的元数据符号 = false |
| file / span | ? | 源码符号必填；`span = {sl, sc, el, ec}` 1 起算 |
| typeKind | enum? | `class` `interface` `struct` `enum` `delegate` `record` |
| baseTypeId | string? | 直接基类 |
| interfaceIds | string[] | 直接实现的接口 |
| modifiers | string[] | `static` `abstract` `virtual` `override` `sealed` `async` `partial` `readonly` `const` `extern` |
| typeRef | TypeRef? | 字段/属性/事件/局部变量的类型 |
| returnType | TypeRef? | 方法 |
| parameters | `{name, type: TypeRef, refKind}`[] | 方法 |
| typeParameters | string[] | |
| attributes | `{typeFqName, args: Value[]}`[] | |
| initializer | Value? | 字段/属性初始化器（§5.4） |
| constantValue | any? | `const` 字段 |
| overridesId | string? | 方法重写的基类方法 |
| isLambda / isLocalFunction | bool | |
| ordinal | int? | lambda/局部函数在外层方法中的序号（源码顺序，0 起） |

| declarations | `{file, span}`[] | partial 类型的全部声明位置 |

`TypeRef = { "id": string?, "fqName": string, "args": TypeRef[] }`

### 5.3 `impl`（接口实现映射）

`{ typeId, interfaceMemberId, implMemberId }` —— 对每个源码类型，对其 `AllInterfaces` 的每个成员调用 `FindImplementationForInterfaceMember` 得到（实现可在基类）。

### 5.4 `Value`（常量折叠与值来源）

所有实参、赋值右侧、初始化器都用 `Value` 表示。每个 Value 都有 `text`（源码文本，最长 200 字符）和 `type: TypeRef?`。

| kind | 字段 | 例 |
|---|---|---|
| `const` | `value`（string/number/bool/null） | `"PosRegister.SSAW0281.Other"`、`25`、`nameof(X)`→`"X"`、`const` 字段 |
| `strings` | `values: string[]`（≤16，排序去重） | `"ToSSAW0907" + (c ? "" : ".employee")` → `["ToSSAW0907","ToSSAW0907.employee"]` |
| `template` | `template: string`（非常量部分为 `{*}`） | `$"shared-bus-{GetRegNo()}-…-{X.ToLower()}-events"` |
| `typeOf` | `typeId` | `typeof(SSAW0001_View)` |
| `staticMember` | `symbolId`, `path: string[]` | `ScreenID.SSAW0907` → path `[]`；`ScreenID.SSAW0907.Id` → path `["Id"]` |
| `memberAccess` | `receiver: Value`, `symbolId` | `dataIni.ButtonClose`、`this.model.tcpModel` |
| `this` | `typeId` | `this` |
| `param` | `methodId`, `index`, `name` | 形参 |
| `local` | `name`, `origin: Value?`, `isLoopIndex`, `loopBound: Value?` | 单次赋值的局部变量给出 origin；`for(i=0;i<x.Count;i++)` 的 i 给出 loopBound=`x` |
| `elementAccess` | `receiver`, `index: Value` | `request.Request["EventPath"]`、`dataIni.ButtonTitle[i]` |
| `objectCreation` | `typeId`, `ctorId`, `args: Arg[]`, `members: {name, symbolId, value}[]`, `elements: Value[][]` | `new SocketRequestData(){EventID=…}`；集合初始化器每个元素 = 传给 `Add` 的实参列表 |
| `tuple` | `items: Value[]` | `(typeof(V), typeof(P))`、目标类型 `new(typeof(V), typeof(P))` 用于 ValueTuple 时也归一为 tuple |
| `methodRef` | `methodId`, `receiver: Value?` | 方法组、`new KeySeqFunction(model.X.M)` |
| `lambda` | `methodId` | lambda / 匿名方法 |
| `callResult` | `callsiteId`, `targetId`, `receiver: Value?`, `args: Arg[]`, `typeArgs: TypeRef[]` | `x.Query<T>("name")`、`GetService<I>()`、`OnGetErrPopupType1(ERRB022)` |
| `conditional` | `whenTrue`, `whenFalse` | `c ? a : b`（字符串可折叠时改用 `strings`） |
| `unknown` | — | 其他 |

`Arg = { paramName: string?, paramIndex: int, value: Value }`（按**形参**对齐；命名实参、可选参数缺省都要处理：缺省参数不出现）。

折叠规则：
- 字符串 `+` 拼接、`string.Concat`、`nameof`、`const` 引用、`static readonly string` 且初始化器可折叠 → `const`。
- 拼接中出现 `conditional`/多值局部变量 → 笛卡尔积展开为 `strings`（超过 16 个 → `template`）。
- 局部变量：方法内所有赋值都可折叠 → 合并为 `const`/`strings`；只有一次赋值 → `local.origin` = 该赋值的 Value；否则 `origin = null`。
- 插值字符串：全部可折叠 → `const`；否则 `template`。
- `x.ToLower()`/`ToUpper()` 作用在可折叠字符串上 → 折叠。
- 嵌套深度 ≤ 6，超过 → `unknown`。

### 5.5 `callsite` / `assign` / `creation`

`callsite`：

| 字段 | 说明 |
|---|---|
| id | §5.6 |
| callerId | 所在方法/lambda/局部函数 |
| targetId | 绑定目标（方法；委托调用时为委托类型的 `Invoke`） |
| targetIsVirtual | 目标为接口成员/虚方法/抽象方法 |
| receiver | Value?（静态调用为 null） |
| typeArgs | TypeRef[] |
| args | Arg[]（含扩展方法的 this 实参，`paramIndex` 按扩展方法定义） |
| isAwaited | bool |
| isConditionalAccess | `?.` 调用 |
| conditions | Condition[]（§5.7） |
| reachable | CFG 可达性（§6.8） |
| order | 在 caller 中的源码顺序（0 起） |
| span | |

`assign`：`{ id, methodId, target: Value, operator: "=" | "+=" | "-=" | "??=" | 其他复合, value: Value, conditions, reachable, order, span }`
——包括字段/属性/局部/元素赋值，以及**事件订阅**（`x.clicked += h`，target 为 `memberAccess` 指向事件符号）。字段/属性**初始化器**不产生 assign（放在 `symbol.initializer`）。

`creation`：`{ id, methodId, value: Value(objectCreation), conditions, reachable, order, span }` —— 每个对象创建表达式一条（即使它已出现在某个 Value 中），用于“谁创建了谁”。

### 5.6 稳定 ID

```text
symbolId   = "s_" + hex(sha1(profileId + "|" + assembly + "|" + docCommentId + extra))[0..20]
             extra: lambda/局部函数 = "~λ" + ordinal（嵌套时逐级拼接）；局部变量 = "~local:" + name + "@" + 声明起始偏移
callsiteId = "c_" + hex(sha1(callerId + "|" + file + "|" + spanStart))[0..20]
assignId   = "a_" + 同上
creationId = "n_" + 同上
evidenceId = "e_" + hex(sha1(file + "|" + sl + ":" + sc + "-" + el + ":" + ec))[0..20]
其余派生 ID（画面边、断链、路径等）= 前缀 + sha1(参与字段的规范化 JSON)[0..20]
```

- 元数据符号没有 docCommentId 时用 `ISymbol.ToDisplayString(FullyQualifiedFormat)`。
- 入库时检测 ID 冲突（同 ID 不同内容）→ 致命诊断 `E_ID_COLLISION`，构建失败。

### 5.7 `Condition`

```json
{
  "kind": "if | switchCase | switchDefault | ternary | loop | catch | logicalRight",
  "polarity": true,
  "mode": "all | any",
  "text": "eventpath.Equals(\"PosRegister.SSAW0281.Other\")",
  "tests": [ { "subject": Value, "op": "equals | notEquals | contains | startsWith | endsWith | switchLabel", "literal": "..." } ],
  "span": { ... }
}
```

- 从语法祖先链收集：`if` 的 then 分支 polarity=true，else 分支 polarity=false；`else if` 链展开为前面各条件 polarity=false + 自身 polarity=true；`switch` 的 case 标签为 `switchLabel`；`?:` 同理；`&&` 右侧加 `logicalRight`。
- `tests` 只收集字符串测试：`a.Equals("x")`、`a == "x"`、`"x".Equals(a)`、`string.Equals(a,"x")`、`a.Contains("x")`、`a.StartsWith("x")`、`a.EndsWith("x")`、`!a.Equals("x")`（notEquals）、`switch(a){case "x":}`。
- 条件表达式为 `A || B` → `mode:any`；`A && B` 或单一 → `mode:all`；被 `!(...)` 包裹的复合条件 → 不收集 tests（只保留 text）。
- 方法含 `goto`/标签时，所有条件附加 `"approximate": true`（结构化祖先链在 goto 存在时不完整）。

### 5.8 其他记录

- `cfg`：`{ methodId, blockCount, hasGoto, unreachableSpans: span[] }`
- `marker`：`{ file, line, dir: "▼|▲", kind, date: string?, author: string?, issueRefs: string[], text }`（日期原样保存，不校验）
- `diag`：`{ severity: "error|warning|info", code, message, file?, line? }`
- `file`：`{ path, assembly, encoding: "utf-8-bom|utf-8|cp932", lineCount, contentHash }`
- `meta`：`{ irVersion: "1", extractor: "csharp-roslyn", profileId, unityDeclared, unityCache?, platformDetected, derivation }`

## 6. C# 抽取器（ScreenFlow.CSharp）

### 6.1 rsp 发现与解析

- 递归枚举 `<project>/<profile.rsp.root>` 下 `*.rsp`；排除名称含 `excludeNamePatterns` 的。
- 解析：逐行；去首尾空白与成对双引号；`@path` 递归读入（检测循环）；选项前缀 `-` 与 `/` 等价、大小写不敏感。
- 识别：`out`、`define`/`d`（可分号分隔多值）、`r`/`reference`（可带 `alias=` 前缀）、`langversion`、`unsafe`、`nullable`、`analyzer`、`target`；其余选项记入 `ignoredOptions`。
- 非选项行且以 `.cs` 结尾（大小写不敏感）→ 源文件；相对路径以工程根为基准。
- 一个 rsp = 一个程序集；程序集名 = `out` 文件名去扩展名。没有 `out` 或没有源文件的 rsp 视为非编译输入，忽略并记 info 诊断。
- 平台识别：define 含 `UNITY_ANDROID` 且不含 `UNITY_EDITOR` → `android`；含 `UNITY_EDITOR` → `editor`；否则 `unknown`。
- 同一程序集名出现在多个 rsp（不同平台/不同 dag）→ 按 profile 的 `selectPlatform` 选择；仍有多个 → 选源文件最多者并发出 `W_DUPLICATE_ASSEMBLY_RSP`。

### 6.2 预检诊断

| 代码 | 条件 |
|---|---|
| `E_NO_COMPILATION_INPUT` | 没有任何可用 rsp |
| `W_UNITY_VERSION_MISMATCH` | `ProjectVersion.txt` 与 rsp 中 Unity 引用路径/define（`UNITY_2022_3_68` 一类）推断的版本不一致；无法推断时 info |
| `W_PLATFORM_DERIVED` | 见 §4.1 |
| `W_REFERENCE_MISSING` | 引用文件不存在（逐个列出） |
| `W_SOURCE_MISSING` | rsp 中的源文件不存在 |
| `I_SOURCE_NOT_IN_RSP` | 工程 `Assets/` 下存在但不在任何选中 rsp 中的 `.cs`/`.CS` |
| `I_NON_UTF8` | 判定为 CP932 的文件 |

### 6.3 编码判定

依次尝试：UTF-8 BOM → 严格 UTF-8（`throwOnInvalidBytes`）→ CP932。`SourceText.From(stream, encoding)` 必须使用判定的编码，保证行列号与编译器一致。

### 6.4 Compilation 构建

- `CSharpParseOptions(LanguageVersion.CSharp9, DocumentationMode.None, preprocessorSymbols: 处理后的 define)`。
- `CSharpCompilationOptions(DynamicallyLinkedLibrary, allowUnsafe: rsp 指定, nullableContextOptions: rsp 指定或 Disable, concurrentBuild: true, deterministic: true)`。
- 程序集依赖图拓扑排序；被引用的源码程序集用 `CompilationReference`；其余用 `MetadataReference.CreateFromFile`。
- 只对 `assemblies.include` 匹配的程序集抽取 IR。
- 编译错误数按程序集汇总为诊断（前 200 条明细）。**不注入伪造类型**；绑定失败的符号/调用 `isCompilerCertain=false` 或 `targetId=null`。

### 6.5 符号抽取

- 遍历每棵语法树的声明 → 源码符号；partial 类型合并为一个 symbol，`declarations` 列出全部位置。
- 调用/赋值/创建中引用到的元数据符号按需输出（`isSource=false`），只输出一次。
- 对每个源码类型输出 `impl` 记录（§5.3）。
- 每个 Enumeration/ScreenID 一类的静态字段，`initializer` 必须是完整折叠的 Value（领域适配器依赖）。

### 6.6 方法体抽取

对每个方法/构造函数/访问器/lambda/局部函数体，用 `SemanticModel.GetOperation` 取得 `IOperation` 树：

| IOperation | 产出 |
|---|---|
| `IInvocationOperation` | callsite（`targetIsVirtual` = 目标 IsVirtual/IsAbstract/IsOverride 或在接口中） |
| `IObjectCreationOperation` | creation + Value `objectCreation`（含 initializer 的成员赋值与集合元素） |
| `IDelegateCreationOperation` | Value `methodRef` / `lambda` |
| `IAnonymousFunctionOperation` / `ILocalFunctionOperation` | 新的方法 symbol（`isLambda`/`isLocalFunction`、`ordinal`、`containerId`）；其体单独抽取 |
| `ISimpleAssignmentOperation` / `ICompoundAssignmentOperation` / `ICoalesceAssignmentOperation` | assign |
| `IEventAssignmentOperation` | assign（operator `+=`/`-=`） |
| 委托 `Invoke`（含 `?.Invoke`、直接 `f(x)`） | callsite，targetId = 委托类型的 `Invoke` |

- lambda 体内的调用属于 lambda symbol，**不**归属外层方法。
- 顺序号 `order` 按源码位置。

### 6.7 变更标记

扫描每个文件的注释 trivia，按 `changeMarkers.pattern` 匹配，输出 `marker`。日期取 `rest` 中第一个 `\d{4}\.\d{1,2}\.\d{1,2}`；作者取紧随其后的 `\S+@\S+`；Issue 引用取 `#\d+`、`[^\s\]]+#\d+`、`T\d{3}-\d+`、`GSEJPOS\d+-\d+`。

### 6.8 控制流

- 对每个方法体：`ControlFlowGraph.Create(IMethodBodyOperation / IAnonymousFunctionOperation 等)`；把 `IsReachable == false` 的基本块中的操作对应的 callsite/assign/creation 标记 `reachable=false`。
- 输出 `cfg` 记录。CFG 创建失败（不完整绑定）→ 全部视为可达并 info 诊断。

### 6.9 并行与内存

- 程序集内按语法树并行（`--parallel N`，默认 `Environment.ProcessorCount/2`），每棵树完成后释放其 SemanticModel 引用。
- 记录按树收集，树内排序后输出到通道；Core 端最终按 ID 排序入库。

## 8. Core 解析服务

### 8.1 符号与派发

- `Dispatch(callsite)`：
  - `targetIsVirtual=false` → `[target]`，certain。
  - 目标是接口成员 → `impls` 中 `interface_member_id = target` 的全部 `impl_member_id`（去重）。
  - 目标是虚/抽象方法 → 目标（非抽象时）+ 所有直接/间接 `overridesId` 指向它的方法。
  - 用接收者具体类型集合（§8.2）收窄；收窄后 1 个 → certain，多个 → candidate（同一 `candidateGroup`），0 个 → 不收窄（保留原候选）。
  - 超过 `maxCandidatesPerDispatch` → 截断（按 ID 升序保留前 N），记 `truncated`。
- 委托调用：接收者 Value 经 §8.2 得到 `lambda`/`methodRef` 集合 → 候选。

### 8.2 值与类型解析（`ValueResolver`）

`ResolveConcrete(Value v, Context ctx) → { values: Value[], types: typeId[], complete: bool }`：

| v.kind | 处理 |
|---|---|
| `this` | types = [当前类型] |
| `objectCreation` | types = [typeId] |
| `lambda`/`methodRef` | values = [v] |
| `memberAccess`（字段/属性）| **字段指向**：收集 `assigns` 中 target_symbol_id = 该符号的全部赋值（含初始化器）；只保留赋值处接收者静态类型与当前接收者静态类型相同或存在继承关系的；递归解析其右值；任何一个解析为 unknown → complete=false |
| `local` | origin 存在 → 递归；否则 complete=false |
| `param` | 若 `ctx.allowParamPropagation`：取全部以本方法为目标的 callsite 的对应实参，递归（深度 ≤ `maxParamPropagationDepth`）；每个结果记录来源 callsite |
| `callResult` | 交给已注册的 `IValueProvider`（领域适配器实现，例如 DI 的 `GetService<T>`）；没有 provider → complete=false |
| `staticMember` | 字段初始化器递归；`path` 非空时交给 `IValueProvider`（例如 `ScreenID.X.Id`） |
| 其他 | complete=false |

`ResolveStrings(Value v, ctx) → { values: string[], complete }`：`const`→1 个；`strings`→多个；`template`→不完整；`staticMember` 经 provider；`param` 经传播；`local`/`memberAccess` 同上。

扩展点（Core 定义接口，UnityPos 实现）：

```csharp
public interface IValueProvider
{
    // 返回 null 表示不处理
    ValueResolution? TryResolve(Value value, ResolveContext ctx);
}
```

### 8.3 断链记录模型（§10 使用）

`why` 模板（`{}` 为替换值），只允许这些：

| TerminalTcpCurrentScreen / StringKeyedDispatchUnmatched | `向对端终端发送事件 {key}，但对端没有任何画面处理该事件路径。` |
| NativeInterop | `调用 Android 原生代码 {key}，其实现不在 C# 源码中。` |
| DatabaseMediated | `从数据库表 {key} 读取数据；该数据由其他处理写入（写入方 {n} 处），调用链在此中断。` |
| DiAmbiguous / MultipleDiRegistrations | `从 DI 取得 {key}，存在 {n} 个注册实现，实际使用哪一个取决于注册顺序。` |
| DiAmbiguous / ReflectionConstruction | `通过反射创建或取得对象（{key}），目标在运行时决定。` |
| DeferredExecution | `处理被放入 {key} 延迟执行，不在当前调用中同步运行。` |
| KeySeqStageDependent | `执行键序事件 {key}。实际处理函数由运行时的当前 Stage 决定；候选 {n} 个。` |
| KeySeqStageDependent / UnresolvedConstantArgument | `执行键序事件，但事件码无法静态确定（{text}）。` |
| Unknown / UnresolvedConstantArgument | `参数无法静态确定（{text}），无法确定目标。` |
| Unknown / UnresolvedSymbol | `调用目标无法绑定（{text}）。` |
| Unknown / TruncatedByDepthLimit | `调用链超过深度上限 {n}，在此截断。` |
| Unknown / TruncatedByCandidateLimit | `候选数超过上限 {n}，在此截断。` |
| Unknown / ScreenNotRegistered | `跳转目标画面 {key} 不在任何画面注册表中。` |

## 9. 领域适配器（ScreenFlow.UnityPos）

每个适配器：`IDomainAdapter { string Id; void Run(DomainContext ctx); }`。`DomainContext` 提供：只读查询 IR 表、写领域表、锚点解析、`ValueResolver`、诊断。

### 9.1 screens
1. 解析 `screens.screenIdType`；其所有 `static readonly` 且初始化器为 `objectCreation`（类型为 ScreenID）的字段 → 画面定义：id = `args[idArgIndex]` 折叠值（失败 → 字段名并 warning），name = `args[nameArgIndex]`，isPopUp = 形参名 `isPopUpParamName` 对应实参（缺省 false）。
2. 对每个 registry：字段初始化器是 `objectCreation`（Dictionary）的 `elements`；每个元素 `[key, value]`：key 为 `staticMember`（ScreenID 字段）、value 为 `tuple` 或 `objectCreation`(ValueTuple)，取 `typeOf` 得到 View/Presenter 类型。同时收集对该字段以常量参数调用的 `Add(key, value)`。
3. 写 `screens`：每个 (terminal, screenId)；在 ScreenID 中存在但未登记的画面写 `terminal = ""`、`registered = 0`。
4. 注册 `IValueProvider`：`staticMember` 指向 ScreenID 字段且 `path == ["Id"]` → 该画面 ID 字符串。

### 9.2 enumerations
基类链包含 `enumerations.baseType` 的类型，其 `static readonly` 字段初始化器的 `args[0]`/`args[1]` 折叠 → `enum_members`。注册 `IValueProvider`：`staticMember` 指向这些字段且 path 为 `["Id"]`/`["Name"]` → 对应值。

### 9.3 ui-bindings（控件、事件、文字键、约束）

对每个已登记画面的 View 类型 V（含其基类链中的源码类型）：

1. **控件字段**：assign 目标为 V 的字段 F，右值（穿透 `local.origin`）为 `callResult`，目标方法名 ∈ `controlQueryMethods`，第 1 实参折叠为字符串 N → 控件 `(F, N, typeArgs[0])`。
2. **列表下标**：V 中目标方法名为 `Add`、接收者为 V 的字段 L 的 callsite，按 `order` 排序，实参为控件字段 → `L[i] = F`。
3. **事件处理**：V 中 assign `operator == "+="`、target 为 `memberAccess(receiver = 控件字段 F, symbol 名 ∈ clickEvents)`，右值经 §8.2 解析为 lambda/methodRef 集合 → `control_handlers`（多个 → candidate）。
4. **文字键**：
   - 直接：assign target 为 `memberAccess(receiver = F 或 F 的成员链, 属性名 ∈ textKeyProperties)`，右值为 `memberAccess(receiver = 类型以 elementDtoSuffix 结尾的字段/形参, 属性 P)` → 控件 F 的文字键 = 初始化 JSON 的 `P` 键，`text_key_source = "json:P"`，certain。
   - 下标：右值为 `elementAccess(receiver = memberAccess(dto, 数组属性 P), index = local(isLoopIndex, loopBound = L))`，且 target 的接收者链中含 `elementAccess(L, 同一下标)` → 对每个 `L[i] = F`：F 的文字键 = JSON `P[i]`，`text_key_source = "json:P[i]"`，**candidate**（模式推断）。
   - 同一控件得到多个不同键 → 全部保留（candidate）。
   - 得不到 → `text_key = null`，`text_key_source = "unresolved"`。
5. **初始化 JSON**：`initJsonDir/initJsonNamePattern`（`{ViewWithoutSuffix}` = V 类型名去掉 `viewSuffix`）。键 `P` 的值即本地化键；数组按下标取。文件不存在 → 诊断。
6. **输入约束**：V 中目标方法名 ∈ `constraintMethods` 的 callsite：值 = `args[constraintValueArgIndex]` 折叠；错误文案实参 `args[constraintMessageArgIndex]` 若为 `memberAccess(…, 属性 Q)` → 在全程序 assign 中找 target 符号 = Q 的赋值，其右值（可经 `memberAccess` 包装，如 `.LocalizeMsg`/`.Msg`）中包含目标 ∈ `errorMessageGetters` 的 `callResult`，其实参折叠为错误码：`staticMember`(ResultStatusCode 成员) → (名称, 值)；`int` 常量 → 反查 ResultStatusCode 成员名（多个同值 → candidate）；`memberAccess(staticMember, Id)` 同理。Q 有多个不同错误码的赋值 → 全部保留（candidate）。每条约束保留其 callsite 的 `conditions` 与所在方法。

### 9.4 di
在 `di.locatorType` 的所有方法（含 lambda）中：
- `callResult/callsite` 目标名 ∈ `registrationMethods`：
  - `typeArgs.Length == 2` → (service = typeArgs[0], impl = typeArgs[1])。
  - `typeArgs.Length == 1` 且无实参 → (T, T)。
  - `typeArgs.Length == 1` 且实参为 lambda → 该 lambda 中目标名 ∈ `factoryResolveMethods` 的 callsite 的 `typeArgs[0]` 为 impl（`via = "factoryAlias"`）；或 lambda 返回 `objectCreation` → 其类型。
- 写 `di_registrations`。
- 注册 `IValueProvider`：`callResult` 目标为 `locatorType.getMethods` → `typeArgs[0]` 的注册 impl 集合（1 个 complete；多个 → 标记 `DiAmbiguous`；0 个 → 不完整）；`getAllMethods` → 全部注册（complete）。
- `domain_edges(kind = "serviceResolve")`：对每个 GetService callsite 记录解析结果（供断链与查询）。

### 9.5 keyseq
1. `keyseq.registerType` 的 `registerMethods` 调用（目标是接口方法或其实现均可）：stage = `args[stageArgIndex]`（`staticMember` → StageNo 成员名）；table = `args[tableArgIndex]` → 经 `local.origin` 得到 `objectCreation`，其 `elements` 中每个元素 = `[objectCreation(KeySeqTableRecord)]`（集合初始化器的单参 Add），取 ctor `args[record*ArgIndex]`：psCode（PsCode 成员名）、func（`methodRef.methodId`）、nextStage。
2. 写 `keyseq_transitions`（含 `sub_table`）。
3. `executeMethods` 的每个 callsite：实参 0 → `objectCreation(KeySeqRequest)` 的成员 `requestPsCodeProperty`，或经 `local.origin` 得到 → psCode；否则 unresolved。
4. 写 `domain_edges(kind = "keySeqDispatch", json = {psCode | null, transitions: [id…]})`。被执行方法本身标记为 `domainHandled`（遍历不进入其方法体）。

### 9.6 navigation
目标 ∈ `managerType.displayMethods` 的 callsite（目标方法声明在 managerType 或其派生类）：`args[screenArgIndex]` 经 §8.2/提供者解析为 ScreenID 字段 → `domain_edges(kind = "navigate", json = {screenIds, mode: "self", popup: 方法名含 Popup})`；无法解析 → `{screenIds: [], unresolvedText}`。`closeMethods` → `domain_edges(kind = "closePopup")`。

### 9.7 tcp
1. **发送**：目标 ∈ `sendMethods` 的 callsite：
   - eventPath = 形参名 `eventPathParamName` 的实参 → `ResolveStrings`（允许形参传播；每个传播来源各自成为一个“有效发送点”）。
   - payload = `payloadParamName` 实参 → 经 `local.origin` 得到 `objectCreation(payloadType)` → 成员 `EventID`、`TargetID` → `ResolveStrings`（`TargetID` 常为 `ScreenID.X.Id`，经 §9.1 提供者折叠；形参传播同上）。
   - 写 `domain_edges(kind = "messageSend", json = {channel: "tcp", keys: [...], keysComplete, eventId, eventIdKind: display|close|common|null, displayTargets: [...], displayMode: screen|popup, effectiveSites: [callsiteId…]})`。
2. **接收方**：实现了某接口方法名为 `receiverInterfaceMethod` 的方法 H，且 H 所在类型 P 在其任意方法中以 `this` 为实参调用了 `receiverRegistrationMethod` → H 为 P 的事件处理方法。P 对应的 (terminal, screenId) 来自 `screens` 表（P 作为 Presenter；也接受 P 为 View）。
   - 主体识别：Condition.tests 的 `subject` 解析后是 `elementAccess(…, const "EventPath")`（可经 `local.origin`）。
   - 收集 H 中所有这种测试的字面量 → `message_handlers.key_literals_json`（`[{op, literal}]`）。
3. 共通事件、`domainHandledReflectionMethods` 中的反射不产生断链。

### 9.8 device / api / native / sql / queue / reflection

| 适配器 | 识别 | 写入 |
|---|---|---|
| device | 目标所属类型 ∈ `commandInterfaces`（或其实现类中实现这些接口成员的方法）的 callsite | `boundaries(category = ExternalHardware, key = 接口名.成员名, requestTypes = 形参类型, responseType = 返回类型解包 Task/UniTask, topicTemplate = 实现类 `topicMethods` 返回 Value 的 template, adapters = 实现类型)`；回流候选 = 实现类的 `callbackMethods` + 全程序传给 `receiveEventSetters` 的 lambda/methodRef；`domain_edges(kind="boundary")` |
| api | 目标名 ∈ `sendMethods` 且声明在 `connectorType` 或其实现 | apiKey = `ApiRequest` 创建的 ctor 实参（形参名 ∈ `apiKeyParamNames`）或字符串重载的同名形参 → `ResolveStrings`；`boundaries(ExternalMicroservice)`，`mockAvailable` = `localMockDir` 下存在含 apiKey 的文件名 |
| native | 创建/调用 `javaTypes` 的类型；`extern` 且带 DllImport 的方法 | `boundaries(NativeInterop, key = 类名 + "." + 方法名字符串)` |
| sql | 任一字符串 `const` 实参匹配 `statementPattern` 且长度 ≥ `minLength` | 轻量分词：`FROM/JOIN/INTO/UPDATE/DELETE FROM` 后的标识符为表名；SELECT 为读，其他为写；`domain_edges(kind="tableAccess", json={tables, mode})`；读操作 → `boundaries(DatabaseMediated, key=表名)`，回流候选 = 写该表的方法 |
| queue | 目标 ∈ `enqueueMethods` 的 callsite，实参中 `objectCreation(requestType)` 的 ctor `args[lambdaArgIndex]` 为 lambda；`deferredInvokers` 目标且实参为 lambda | `domain_edges(kind="enqueue", json={lambdaIds, queue: 方法全名})` |
| reflection | 目标为 `System.Type.GetConstructor/GetField/GetMethod/GetProperty`、`ConstructorInfo.Invoke`、`MethodInfo.Invoke`、`Activator.CreateInstance`，且所在方法不在 `domainHandledReflectionMethods` | `boundaries(DiAmbiguous, reason ReflectionConstruction)` |

### 9.9 资源解析

| 资源 | 解析器 | 要点 |
|---|---|---|
| UXML | `XmlReader`（`DtdProcessing.Prohibit`、`XmlResolver = null`、`IgnoreComments`） | 元素名取本地名（类型全名）；属性 `name`；层级路径 = 祖先 `name`（无 name 用元素本地名）以 `/` 连接；不校验命名空间声明（`xsi=` 非标准） |
| 初始化 JSON | `System.Text.Json`（允许尾逗号、注释） | 保留原始结构 |
| 本地化 YAML | **自写行解析器**（禁止引入 YAML 库） | 见下 |
| 错误文案 JSON | `System.Text.Json` | 数组；按 `errorMessageLocaleFields` 写 `messages` |

本地化 YAML 行解析器：
- 识别 `m_Name:`、`m_TableCollectionName:`、`m_TableCollectionNameGuidString:`、`m_LocaleId:` 下的 `m_Code:`、`m_SharedData: {… guid: X …}`。
- `m_Entries:` 下的 `- m_Id: <数字>` + `m_Key: <标量>`；`m_TableData:` 下的 `- m_Id:` + `m_Localized: <标量>`。
- 标量：双引号（处理 `\uXXXX` `\n` `\t` `\"` `\\` `\/`，以及行尾 `\` 续行与折行：续行去前导空白、换行折为空格）、单引号（`''` → `'`，折行同上）、无引号（到行尾，后续缩进更深的行折为空格续接）、空。
- 关联：语言表 `m_SharedData.guid` = 共享表 `m_TableCollectionNameGuidString`。
- `text_plain`：`<br>` 与 `\n` → `\n`；删除所有 `<...>` 标签；不 trim 中间空白，去首尾空白。

### 9.10 entries（画面入口）
对每个已登记画面 (terminal, screenId, V, P)：
- `click`：V 的 `control_handlers` → entry(control_id, handler)。
- `auto`：P 中名为 `autoEntryMethods` 的方法。
- `scan`：P 实现名为 `scanEntryMethods` 的方法且 P 以 `this` 调用了 `scanRegistrationMethod` → entry(trigger="scan")，并在该入口记一个 ExternalHardware 断链（扫描输入来自外部设备，`resume = single` 指向该方法）。

## 10. 画面操作图（Core：`ScreenGraphBuilder`）

### 10.1 遍历状态

`State = { methodId, terminal, branchFilter: {channel, keys[]}?, depth, chain[], conditions[], breaks[], deferred }`

### 10.2 算法

对每个 entry（按 ID 排序）：从 `(entry.method, entry.terminal)` 开始深度优先遍历；`visited` 以 `(methodId, terminal, branchFilterHash)` 为键，防止循环。

对当前方法的 callsite（按 `order`，跳过 `reachable=false`），先检查 branchFilter（§10.3），再按以下优先级处理：

1. 有 `domain_edges`：
   - `navigate`：每个 screenId → 产出画面边 `(entry.terminal, entry.screen) → (state.terminal, screenId)`；不在 `screens` 中 → Unknown/ScreenNotRegistered 断链 + 悬空边。继续处理后续 callsite。
   - `closePopup`：链上记录事件，不产出边。
   - `messageSend`：目标终端 = peer(state.terminal)。
     - 有 `displayTargets` → 对每个目标产出画面边（到 peer 终端）；然后接收方 = 该目标画面的 `message_handlers` 中匹配 keys 的处理方法（candidate）。
     - 无 `displayTargets` → 接收方 = peer 终端全部匹配 keys 的处理方法；记 `TerminalTcpCurrentScreen` 断链（有候选：resume multiple/single；无：reason StringKeyedDispatchUnmatched，resume none → 悬空边）。
     - 每个接收方：进入其处理方法，`terminal = peer`，`branchFilter = {tcp, keys}`，条件追加 `对端当前画面 ∈ {接收方所属画面}`；若 `tcp.receiveDeferred` → `deferred = true`。
     - keys 不完整（template/unknown）→ Unknown/UnresolvedConstantArgument 断链 + 悬空边。
   - `keySeqDispatch`：psCode 已知 → 记 `KeySeqStageDependent` 断链（resume = 全部匹配 transition 的 handler）；对每个 handler 进入，条件追加 `当前 Stage = {stage}`，链上记录 `nextStage`。psCode 未知 → 断链（UnresolvedConstantArgument，resume none）+ 悬空边。不进入被执行方法本身。
   - `enqueue`：记 `DeferredExecution` 断链（resume single），进入 lambda，`deferred = true`。
   - `boundary`：记对应断链；ExternalHardware 进入回流候选（各自独立分支，条件追加 `硬件响应到达`）；ExternalMicroservice 不进入任何方法（继续处理当前方法后续 callsite，因为 await 后的代码在同一方法中）；DatabaseMediated 只记录；NativeInterop 只记录；ReflectionConstruction 只记录。
   - `serviceResolve`：不改变遍历，仅供 §8.1 收窄。
2. 无领域边：`Dispatch(callsite)`：
   - 目标为源码方法且命名空间不在 `doNotDescendNamespaces` → 进入（候选全部进入）。
   - 目标为元数据方法，且有实参为 lambda/methodRef → 进入这些 lambda/方法；目标 ∈ `deferredInvokers` 时 `deferred = true`；否则视为同步调用（candidate）。
   - `targetId == null` → Unknown/UnresolvedSymbol 断链（只记录，不悬空）。
3. 深度超过 `maxChainDepth` → Unknown/TruncatedByDepthLimit 断链 + 悬空边。

### 10.3 分支过滤（接收方处理方法内部）

当 `state.branchFilter` 存在且当前方法是接收方处理方法：callsite 的 `conditions` 中，主体为 EventPath 的 tests 构成约束，对 keys 集合 K：
- polarity=true, mode=all：存在 k∈K 满足全部 tests；
- polarity=true, mode=any：存在 k∈K 满足任一 test；
- polarity=false, mode=all：存在 k∈K 使得“全部 tests 都满足”不成立；
- polarity=false, mode=any：存在 k∈K 一个 test 都不满足。

所有约束都满足才处理该 callsite；没有 EventPath 约束的 callsite 一律处理。只有部分 k 满足 → 该 callsite 之后的链确认度降为 candidate。
判定：`equals`：k == lit；`notEquals`：k != lit；`contains/startsWith/endsWith`：按字面；`switchLabel` 同 equals。区分大小写。

`branchFilter` 只在接收方处理方法本身生效；进入其调用的其他方法后清除。

### 10.4 画面边

```json
{
  "edgeId": "se_…",
  "from": { "terminal": "customer", "screenId": "SSAW0903" },
  "to":   { "terminal": "customer", "screenId": "SSAW0907" },
  "trigger": { "kind": "click | auto | scan", "controlId": "selectCharge_Other", "entryMethodId": "…" },
  "confidence": "certain | candidate",
  "conditions": [ "员工面当前画面 ∈ {SSAW0089}", "当前 Stage = CSP_NML_…" ],
  "chain": [ ChainStep ],
  "breakIds": [ "b_…" ],
  "endsAtBreak": null,
  "cost": 4.25,
  "truncated": false
}
```

`ChainStep = { order, kind: "call|lambda|navigate|socketSend|socketReceive|remoteDisplay|keySeqDispatch|enqueue|deviceCommand|deviceCallback|apiCall|dbRead|dbWrite|closePopup", terminal, methodId, namespace, type, method, file, line, confidence, deferred, detail, evidenceId }`

- `confidence`：链上全部步骤 certain 且无断链 → certain；否则 candidate。
- 同一 `(from, to, trigger.kind, controlId)` 的不同链最多保留 `maxChainsPerScreenEdge` 条（按 cost、再按 edgeId），超出记 `truncated`。
- 悬空边：`to = null`，`endsAtBreak = breakId`。
- `cost = 1.0 + 0.5×[candidate] + 0.2×[任一步 deferred] + 0.75×断链数`（悬空边额外 +2.0）。

### 10.5 断链去重

断链 ID 由 `(category, reason, at.callsiteId, contract.key)` 决定；不同画面边经过同一断点共用一条断链记录。

### 11.5 路径搜索算法

1. 终端未指定 → 查 `screens` 中该 ID 的全部终端，逐个组合计算并合并（结果中注明终端）。
2. 画面级折叠图：同一 `(from, to)` 的平行边取最小 cost 作为折叠边；悬空边不参与。
3. Yen K 最短无环路径（无环以 `(terminal, screenId)` 为单位），Dijkstra 平局按折叠边的最小 edgeId 升序。
4. 每一跳展开该 `(from, to)` 的全部平行边（按 cost、edgeId 排序，最多 10 条，超出标 `edgesTruncated`）。
5. 完整路径不足 K 条 → 计算从起点可达（≤ maxHops）的画面中出发的悬空边，按“到达该画面的最短 cost + 悬空边 cost”排序，取前 K 条作为 `partialPaths`。
6. `diagnosis`：终点没有任何入边 → `targetHasInboundEdges=false`，`note` 说明并列出引用终点画面 ID 的位置数量（`navigate`/`messageSend` 中 screenIds/displayTargets 含该 ID 但所在链未能形成画面边的 callsite）。
7. `--include-prefix`：从 `standbyScreens` 到 from 再跑一次（K=1），放在 `prefixPath`。
8. `--detail summary`：不含 `chain`；`full`：含。

## 12. Python MCP 服务（`python/screenflow_mcp`）

- 只做调用层：参数校验 → 子进程调用 CLI → 原样返回信封 JSON（解析后的 dict）。**不包含任何解析逻辑。**
- 配置（环境变量）：`SCREENFLOW_CLI`（可执行文件路径或 `dotnet …dll`）、`SCREENFLOW_DB_DIR`、`SCREENFLOW_PROFILE`（默认 `android-onsite`）、`SCREENFLOW_PROJECT`（证据片段读取用）、`SCREENFLOW_TIMEOUT_SEC`（默认 120）。
- 工具清单与参数见 `04_运行时Agent设计书.md` §2。
- 子进程：`subprocess.run([...], capture_output=True, text=True, encoding="utf-8", timeout=…)`，参数用列表传递（禁止 shell 拼接）。
- CLI 退出码非 0 且 stdout 为合法信封 → 原样返回；stdout 非法 → 返回 `{"ok": false, "error": {"code": "E_CLI_FAILURE", "message": stderr 末尾 2,000 字符}}`。
