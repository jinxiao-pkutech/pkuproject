# 05 测试与验证规范

## 1. 测试分层

| 层 | 位置 | 在哪台机器跑 | 内容 |
|---|---|---|---|
| 单元测试 | `tests/*.Tests/` | 生成机器 | 每个模块的纯函数/小输入 |
| 夹具测试 | `tests/*.Tests/` + `tests/fixtures/MiniPos/` | 生成机器 | 对仿真工程完整构建索引后断言期望事实（§4） |
| 确定性测试 | `tests/ScreenFlow.Cli.Tests/` | 生成机器 | 两次构建导出 SHA-256 一致 |
| 架构测试 | `tests/ScreenFlow.Architecture.Tests/` | 生成机器 | 依赖规则（02 §1.1） |
| Python 测试 | `python/tests/` | 生成机器 | MCP 层（用假 CLI） |
| 本机验收 | `acceptance/` | **本机（有真实源码）** | §6 清单 |

- 每个 xUnit 测试加 `[Trait("Task", "Txx")]`，与任务书对应，冒烟命令按 Trait 过滤。
- 测试命名：`<被测对象>_<场景>_<期望>`。
- **禁止**：跳过测试、`Assert.True(true)`、把实际输出复制为期望值（期望值必须来自本文档或 03 文档）。

## 2. 冒烟测试

每个任务书给出冒烟命令，最少包含：

```bash
dotnet build ScreenFlow.sln -c Release
dotnet test ScreenFlow.sln -c Release --filter "Task=Txx"
```

冒烟通过 = 构建无警告无错误 + 过滤后的测试全部通过 + 之前所有任务的测试仍然通过（每 5 个任务跑一次全量 `dotnet test`，任务书中注明）。

## 3. 仿真工程 `tests/fixtures/MiniPos/`

- 按 `03_源码事实手册.md` 的**真实形态**仿造：同样的文件路径、命名空间、类名、方法签名、调用写法。
- 体量小（约 40 个 `.cs` 文件），但每种机制和每类断链至少出现一次。
- 夹具工程必须能被 Roslyn **无错误编译**（`fixture` 配置下诊断中 error = 0）。
- 外部库用 `Assets/Stubs/` 下的源码桩代替（命名空间与真实库一致），只写编译所需的最小成员。

## 6. 本机验收清单（在有真实源码的机器上由用户执行）

### 6.1 前提

1. 安装 Unity **2022.3.68f1** 与 Android Build Support；**不要**用其他 Unity 版本打开工程（会触发升级）。
2. 用该版本打开 `sej_client_pos_unity`，等待脚本编译完成（生成 Editor 的 rsp）。
3. 切换平台到 Android，执行一次 Player 构建（Development 即可），以生成 Android Player 的 rsp。
4. 安装 .NET 8 SDK（`dotnet --list-sdks` 能看到 8.x）、Python 3.11+。
5. 在 `myTestV1/` 执行：`dotnet publish src/ScreenFlow.Cli -c Release -o publish`；`pip install -e python`。
